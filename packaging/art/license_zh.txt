07 · 能力边界（做与不做）


  这份文档同时是**安装向导里的许可页文本**（由 `tools/build.py` 从本文件生成 `packaging/art/license.txt`，
  单一来源，不手抄两份）。所以：改动这里会直接改变安装时用户看到的边界声明。

一句话


只用**合法可观察**的手段采集：把"我能看见什么"做到最强，把"我要突破什么"一律不做。

做（合规鲁棒性，做到最强）


  **诚实身份**：默认带一个说明用途的 UA（`Daedalus/<版本> (personal data collector; ...)`），
  不伪装浏览器指纹、不伪造 Referer 来源。
  **礼貌优先**：按域限速 + 并发上限 + 原子预约的礼貌间隔；`Retry-After` 优先且**带上限**（默认 300s）；
  域冷却**跨重启保留**（不会因为重启而"忘记"该站的休息）。
  **robots 规则**：按 RFC 9309 语义执行（404/4xx → 视为不存在；5xx/不可达 → 按**完全禁止**；
  最长匹配优先、平票时 Allow 胜；缓存 ≤24h）。
  **会话复用**：cookies（Netscape / JSON / 浏览器导出）→ 会话 jar，DPAPI 密文落盘，
  用于**你自己有权访问**的会话。
  **未改装的浏览器**：真实浏览器访问公开页并做**网络观察**（进程/上下文/页三层槽位、逐条子资源判定），
  用于"内容空壳"的页面——但仅此而已。
  **拦截识别与处置**：能说清"被拦在哪、为什么"（状态码、`Retry-After`、被拦的 URL 与原因都落进事实层），
  并**分级退避 → 降速 → 停止 → 报告 → 放弃该站并留理由**。
  **授权目标拉满**：对**你自己的站点、合作方授权范围、官方 API**，可以把并发与强度开到资源计划允许的上限。

不做（突破对方防护；本工程从架构上就没留位置）


  隐身注入 / 指纹伪装 / `navigator.webdriver` 改写；
  验证码识别或打码平台对接；
  请求签名伪造（各类站点的风控签名算法）；
  出口 IP 轮换、代理池、账号池；
  行为拟人（模拟人类节奏/鼠标轨迹以规避风控）；
  绕过登录、付费墙、访问控制或速率限制的技术手段。

**为什么这些不做**（三条理由，任何一条单独成立）：

1. **越过了本工程自己写的红线**：三份设计文档、《02》的 C4 条、以及机主明确确认的边界，
   都把"不突破对方防护"列为不可协商项。架构上顶层只留三个专家（直连网络/浏览器运行时/制品与媒体），
   没有任何"对抗"位置。
2. **这类能力无法自证有效**：Kiana 的坑账自述"无量化证据、离线测不了"。做进去就要宣称它有效，
   而工程上给不出可验收判据——那就是把"没验证"包装成"已实现"。
3. **代价与收益不对称**：为了绕过一个站点的风控，要维护一整套随目标变化而失效的实现，
   而本工程的正当用途（自有/授权/公开数据）根本不需要它。

被拦了怎么办（这才是本工程的正解）


| 现象 | 处置 | 你能看到什么 |
|---|---|---|
| 429 / 503 / `Retry-After` | **不重试、不换 IP**：独立计数冷却 + 退避，连续 N 次转死信 | `net.throttled`、`throttles` 计数、台账条目、告警 |
| robots 不允许 | 入队前就拒绝（`policy_denied`），零出网 | 任务状态 `policy_denied` + 可读原因 |
| SSRF 闸拦截（私网/保留地址） | 不可重试，立即停 | 证据里的 `policy_denied` + 具体地址 |
| 内容始终空壳/验证页 | 记 `browser` 候选或质量拒收，**不升级为对抗手段** | 质量分与原因、浏览器候选证据 |
| 站点整体拒绝我们 | 停止该站，写清理由，转下一个目标 | 台账 `policy_denied`，可导出审计 |

环境变量与开关（"变通"的合法形式）


  **代理只从环境变量读**（`HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`）：不提供"随便填个代理"的接口，
  也不做轮换。
  **可插拔而非改形状**：任何**合法**的新采集方式（官方 API、授权数据源、自建代理、外部工具）
  都能作为适配器/执行资源插进来——加一个来源 = 加一个文件，核心不为对抗手段改形状。
  `respect_robots` 可以关（配置项存在），但**关掉它请先想清楚**：那是你自己的合规红线，
  引擎不会替你判断。CLI 里没有对应开关，就是不想让这件事变得顺手。

用户自己负责的部分（说清楚，不含糊）


  你采集的目标必须是你**有权访问**的；本工程不替你判断授权，也不提供绕过授权的能力。
  采集到的数据由你负责处置（本机的脱敏开关只影响**展示与导出**，**原始层永不脱敏**——
  脱了就不能重放，等于把事实毁了）。
  卸载程序**不会删除你的数据**；要删是单独勾选的显式动作。
