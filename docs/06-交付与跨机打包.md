# 06 · 交付与跨机打包

> 目标：**本机打包 → 未装过的新机器装完即可用**。三条边界不可违背：
> **不静默安装**、**缺件硬报错**、**绝不写解包临时目录**。

## 一、产物形态

| 产物 | 说明 |
|---|---|
| `dist/daedalus/` | PyInstaller **one-dir**：`daedalus.exe`（GUI，窗口子系统）+ `daedalus-cli.exe`（控制台）+ `_internal/` |
| `dist/Daedalus-Setup-<版本>.exe` | 自制 NSIS 安装向导（默认完整向导，含许可页/组件页/自检页） |
| 便携版 | 直接拷贝 `dist/daedalus/` + 放一个空的 `portable.flag` 即可（数据落在同级 `DaedalusData/`） |

**为什么是 one-dir + 两个 EXE**（写在 `packaging/daedalus.spec` 里）：
one-file 每次启动都要解包几百 MB 到临时目录（慢，且杀软爱报毒）；
Windows 下一个 EXE 只能是窗口或控制台子系统，GUI 要"无黑窗"、CLI 要被管道读，硬合成一个两边都难用。
安装器打成一个单文件 `Setup.exe`，用户看到的与"单 EXE"体验一致。

## 二、数据根规则（唯一实现：`privacy/secrets.py`）

| 场景 | 数据根 | 怎么判定 |
|---|---|---|
| 测试/自定 | `$DAEDALUS_DATA_ROOT` | 环境变量优先 |
| **便携** | `<exe 同级>/DaedalusData` | `DAEDALUS_PORTABLE=1`，**或**同级存在 `portable.flag` / `DaedalusData/` |
| 安装版 | `%LOCALAPPDATA%\Daedalus`（回退 `%APPDATA%` → 家目录） | 默认 |

⚠️ **绝不使用**打包器的解包临时目录（`sys._MEIPASS`）：那是升级时会被清掉的地方
（Kiana 的便携数据就是这样被整个删掉的）。

## 三、安装向导（`packaging/installer.nsi`）

- **默认完整向导**：欢迎 → 许可（内容由 `docs/07-能力边界.md` **生成**）→ 组件 →
  目录 → 安装 → 完成（可勾选"运行安装自检"= `daedalus-cli doctor`）；
- 语言 zh-CN / ja-JP / en-US，跟随系统预选；
- `ManifestDPIAware true`（否则高分屏整窗位图拉伸、字体全糊）；
- **不静默安装**：检测到 `/S` 直接拒绝并说明理由（自动化部署请用便携版）；
- **不代下载**：浏览器运行时不随包分发（体积/许可），勾选只记意图并打印确切命令；
- 安装时**先删目标子目录**（防新旧依赖混跑）；版本徽章从 `version.nsh` 读（单一来源）；
- 安装日志不含敏感信息（只输出路径与步骤）。

## 四、卸载向导（三条硬规矩，来自 Kiana 三次真实事故）

| 规矩 | 实现 | 不这么做会怎样 |
|---|---|---|
| 卸载段全部带 **`un.` 前缀** | 每个卸载 Section 名以 `un.` 开头；函数用 `Function un.*` | NSIS 会在**安装时**执行卸载逻辑 → 装完即被删光 |
| **延迟扫尾**删自身 | 卸载器删不掉运行中的自己：写 `%TEMP%\daedalus_uninstall.bat`（ping 延迟 3 秒 → `rmdir /s /q "$INSTDIR"` → 自删）后 `Exec` 脱离 | 目录残留、下次安装冲突 |
| **共享资源条件化清理** | 判据是安装时写的 `install.marker`：**不是我们登记的安装 → 什么都不动**（弹窗告知）；是我们的 → 删快捷方式/注册表项；分支之间显式 `Goto` 互斥 | 删掉别人的文件；或"恢复完又走删除" |

**用户数据默认保留**：数据在 `%LOCALAPPDATA%\Daedalus`，不在安装目录里，
删除数据是一个**默认不勾**的可选段，并明确写着"不可恢复"；完成页再重申"您的数据不会被删除"。

## 五、版本号单一来源（四件套）

唯一来源：`src/daedalus/__init__.py` 的 `VERSION`。由 `tools/version_check.py` 生成/校验：

| # | 消费方 | 文件 |
|---|---|---|
| 1 | Python 包内（界面/CLI/报告/doctor 都读它） | `daedalus.VERSION` / `about()` |
| 2 | 安装脚本（显示名 + `VIProductVersion`） | `packaging/version.nsh`（生成） |
| 3 | EXE 文件属性（右键属性→详细信息） | `packaging/version_info.txt`（生成） |
| 4 | 发行元数据 | `pyproject.toml`（生成） |

校验命令：`python tools/version_check.py`（不一致 → 退出码 1；`--write` 重新生成）。
它还会全仓扫描"硬编码版本字面量"（单一来源之外的不许有）。

## 六、构建（`tools/build.py`）

```
python tools/build.py                 # 完整：版本校验 → 美术 → PyInstaller → NSIS
python tools/build.py --exe-only      # 只出 onedir（不上安装器）
python tools/build.py --art-only      # 只重生成安装器美术
python tools/build.py --dry-run       # **先自证**：列出会做什么，并校验缺件，不写任何产物
```

四条纪律：
1. **缺件硬报错**：PyInstaller / NSIS / 图标 / 关键资源任一缺失 → **中止构建**并说清装什么；
   `--exe-only` 是唯一的显式逃生开关；
2. **dry-run 先自证**：`--dry-run` 打印将要执行的每一步与缺件结论，**不创建任何文件**；
3. **产物核对**：构建后检查两个 EXE、`_internal`、资源、版本资源都在（少一个就报错）；
4. **用 python subprocess 调 makensis**：Git Bash/MSYS 会把 `/S` 之类参数改写成 `S:\` 路径。

## 七、交付前核对（发版门禁）

| # | 检查 | 怎么检 |
|---|---|---|
| 1 | 版本四件套一致 | `python tools/version_check.py` |
| 2 | 解包**无** cookie/主密钥/敏感配置 | `python tools/build.py --verify-package`（扫描 `dist/` 里的已知敏感文件名与内容特征） |
| 3 | 安装器静态规矩（`un.` 前缀、拒绝 `/S`、条件清理、DPI、数据保留） | `tests/gates/s10b_gate.py` |
| 4 | 装/卸**实测** | 需要**未安装过的机器或干净测试账户**（PENDING P20，本机不拿正式安装当试验田） |
| 5 | 装完即可跑（浏览器/ffmpeg 就绪探测通过） | 安装向导完成页的 `doctor` 自检；缺件会明确说缺什么 |
| 6 | 便携版可拷可用 | 拷贝 `dist/daedalus/` + `portable.flag`，双击 → 数据落在同级 `DaedalusData/` |

## 八、明确的未验证项（不许含糊）

- **未装过的新机器上安装**：本机没有第二台干净机器/干净账户 → 标记**未验证**（P20）；
- **浏览器二进制**：本机已就绪（chromium 1234）；新机器需 `python -m playwright install chromium`
  （安装器**只提示不代下载**，符合"不静默安装"）；
- **代码签名**：本工程**不做**签名（自用与授权范围），所以 Windows SmartScreen 可能提示未知发布者——
  这是如实的行为，不是缺陷。
