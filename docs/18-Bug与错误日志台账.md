# 18 · Bug 与错误日志台账（踩坑记录）

> **用途**：本工程从开工到"可交付"期间**真实出现过的每一个 bug / 报错 / 坑**，逐条记下
> **报错原文 → 根因 → 修法 → 谁抓到的 → 防复发的机制**。
> 目的很直白：**下次别再踩同一个坑**。改代码前先在本文件里搜一眼。
>
> 与其它文档的分工：`docs/05` 是"**预先想到**的坑 + 对策"（面向设计），
> 本文件是"**真实发生过**的坑"（面向排错）。两者互补，不要合并。
>
> 编号规则：`B<阶段>-<序号>`；**加粗的条目**是"不修就会静默出错"的那类（最危险）。

## 三、几条**反复出现**的教训（比单个 bug 更值得记）

1. **桩太多会漏真 bug**。B4-1（robots 自递归）能躲过 S1–S8 八门，是因为每个门禁都注入了 robots 桩——
   谁都没跑过"真 Fetcher + 真 RobotsCache"的拼接。**对策**：关键拼接处要有一条"真对象 + 假传输层"的用例
   （只换最外层的网络，逻辑全真）。
2. **门禁自己也会错**，而且假红比假绿更浪费时间。本轮出现三次：把"关掉开关"当合法配置（B17-1）、
   把文档字符串/注释当违规（B8-6、B10-7）、把机器负载当性能回归（B17-6）。
   **对策**：规则只扫**可执行代码**（AST 剥字符串）；"测不准"要作为一等事实输出，而不是让门禁猜。
3. **打包态与源码态是两个世界**。B10-3（GBK 控制台）、B10-1（NSIS BOM）、B10-5（版本断言）
   都只在打包或真机上暴露。**对策**：构建后**必须**跑一次打包态冒烟（`dist/daedalus-cli.exe doctor`），
   并且安装器静态规矩要进门禁。
4. **"看起来成功"是最危险的形态**：B2-2（整批回滚）、B7-1（白等 1 秒）、B8-1（双取+UA 泄漏）、
   B9-2（写线程静默停摆）都属于"没有任何报错，但结果不对"。**对策**：每条关键路径都要问一句
   "如果它悄悄错了，我怎么发现？"——答不上来的地方就补指标/断言。
5. **一次抓到 5 个**（B6 那一轮）说明：**接口形状不一致、终态被二次推导、事实在传递中被过滤**——
   这三类是同一族问题（"信息在层间丢了"）。**对策**：跨层传的东西**只增不减**；终态由裁决者定义，
   执行者只记账。

## 四、怎么用这份文件

- **改代码前**：搜一下你正在动的那一块（比如"改脱敏"就先看 B1/B17）。
- **门禁红了**：先对照"⚪ 工程/测试"那几条，确认不是门禁自己错了（假红）。
- **要加新阶段**：把新踩到的坑按 `B<阶段>-<序号>` 追加到对应小节，并在"防复发"列写上门禁编号——
  **没有门禁的修复等于没修**（下次还会回来）。
- **交付前**：`docs/17`（安全自审）与这份文件一起看，前者说"防线在哪、哪没查"，后者说"防线是怎么补上的"。
