# 11 · 设计补充：脱敏开关（按数据类型）与指纹可见性

> 这是机主在施工前追加的要求，**不塞进施工计划**，作为独立设计补充；落地后回填"实现位置"列。
> 一句话：**脱敏不是一个总开关，而是按数据类型的多个开关；开关状态必须透明可见；指纹必须看得见。**

## 一、脱敏开关矩阵（作用于"输出面"，原始层除外）

| # | 数据类型 | 默认 | 关闭后的行为 | 实现位置（待回填） | 备注 |
|---|---|---|---|---|---|
| S1 | 日志·URL 查询参数（`?token=` 等） | **脱** | 日志输出原文 | `obs/logging_sanitizer.py` + 策略层 | 关闭有风险：日志最常被分享 |
| S2 | 日志·请求/响应头（Cookie/Authorization） | **脱** | 原文 | 同上 | |
| S3 | 日志·正文文本（手机/邮箱/IP） | **脱** | 原文 | 同上 | |
| S4 | 导出副本（整条记录） | **不脱** | 原文 | `store/export.py` → `sanitize_record` | 个人使用：导出要原始数据 |
| S5 | 派生记录落库 | **不脱** | 原文 | `understand/*` → 写库路径 | |
| S6 | 元数据落库的 `headers` | **脱** | 原文 | `store/db.py` 写库前 | 落库的是"给人看"的历史，不是运行钥匙 |
| S7 | UI 展示 | **不脱** | 原文 | `ui/pages/*` | 你自己看 |
| S8 | 原始层 raw bytes / raw 元数据 | **永不脱（不可配置）** | — | `capture/rawstore.py` | **写死**：脱了就不能重放（第一性原则） |

**正交性要求**：关掉任一类，**不得**影响其它类的行为（终检 C6 逐类验证）。
**运行态钥匙不脱**：队列表里的 URL、下载直链、Cookie **原样**保存与使用（脱了会 403、任务卡死）；
这一条写进代码注释，防后人"顺手补闸"。

## 二、透明规则（不许静默）

1. **可查**：`dae config show` 与 GUI 设置页显示每类开关的当前值（脱/不脱）。
2. **告知**：启动时若有任一类被关闭 → 日志打一条 `INFO`（形如 `sanitization: 2 项已关闭（S4,S5）`）
   + GUI 状态栏显示徽章 `脱敏：N 项已关闭`。
3. **不谎报**：所有提示语由**实现结果**决定——DPAPI 不可用就如实显示"本机未加密（明文落盘）"，
   不许界面写"已加密"而实现是明文（Kiana 事故）。
4. **变更留痕**：每次开关变更写进 DEVLOG 与运行日志（谁改的、从什么改成什么）。

## 三、指纹可见性

| 项 | 要求 | 实现位置（待回填） |
|---|---|---|
| 内容指纹 | 每条记录可查**去重指纹**（`content_hash`，16 hex）与**完整性哈希**（`stream_hash`，全长 sha256） | `frontier/dedup.py` + `capture/rawstore.py` |
| 近似指纹 | 显示 `simhash`（**入库前 `clamp63`**）与**汉明距离** | 同上 + 写库路径强制钳位 |
| 命中解释 | 去重命中时给出**可读原因**：`与 <父记录指纹短码> 重复（汉明距离 N，阈值 T）` | `understand/dedup_hooks.py` |
| 阈值可调 | 近似阈值可配（默认 3，范围 2–4），改动记 DEVLOG | 配置层 |
| 算法版本 | 指纹带 `FINGERPRINT_VERSION`（已实现于 `frontier/dedup.py`）：**新旧值可比不可混** | 已完成 |
| 变更台账 | 每次运行产出 **新增 / 未变 / 更新 / 失败 / 被策略拒绝** 五态计数，可查可导出 | `obs/metrics.py` + `store/export.py` |
| 导出含指纹 | 导出（jsonl/csv）含指纹列，便于离线核对"为什么被去重" | `store/export.py` |

**C8**（不谎报）、**C10**（原始层永不脱敏）、**D3**（阈值可解释）、**D4**（指纹可见）、**D7**（版本可比不可混）。
