## 2026-09-23 · UI 走查（28 项）：组件全对、**接线全没接**；界面语言跟随本机 + 打包态 JSON 编码事故

**为什么**：机主要求"人实操测一遍 UI、背景图选文件、取色这些杂七杂八的智能取色、深度定制化可玩性、
布局参考 Kiana 别太拥挤；**装完之后语言要跟本机，选过简体就不许蹦日文**"。

**做法**：先写走查脚本 `tools/ui_walk.py`（28 项，桩掉对话框、**走真实信号路径**），再按结果改。
→ 结果：**28/28 全过**；但**改之前它抓出了 5 个 bug**，全都是"组件本身没问题、接线没接"这一类：

| 走查抓到 | 真相 |
|---|---|
| 改透明度/主题/密度/字号，界面纹丝不动 | `build_headless()` **从来没装过变更处理器**；`run_ui()` 装的是另一份 |
| 选好背景图，底图不出现、取色也不跑 | 设置页只把路径写进 `SettingsStore`，**没有任何人读它去执行** |
| 手工选的强调色被自动取色悄悄改掉 | 自动取色在"外观参数变了"就无条件跑，没排除"用户刚显式选过色" |
| 切到日文后旧中文文案还挂着 | 只重刷了 QSS；文案是**建控件时写死的** |
| 紫图取色取成灰 | 下采样用 `INTER_AREA` 把邻近色平均成一团中间色 → 取色改**最近邻** |

**根因是同一句话**：原来 S10 的 UI 用例是直接调 `set_wallpaper()` 这类**组件方法**验收的，
所以"设置里存了底图、界面从不加载"能一路假绿到打包。**修法**：抽出唯一的接线点
`MainWindow.wire_context(win, store, ctx)`（**两条启动路径共用**），门禁一律走
"改控件 → 信号 → 存盘 → 通知 → 界面更新"，并断言 `win._ui["applied"]`（真进样式的值）而不是落盘值。

**多语言**：新增 `ui/i18n.py`（80 键 × zh-CN/ja-JP/en-US）；解析顺序
**设置 > 安装器 `install.marker` 的 `lang=` > 系统 UI 语言 > en-US**；NSIS 把 `$LANGUAGE` 写进标记；
`--json doctor` 输出 `ui` 段（locale/source/setting/installer/system）——装机后"为什么是这门语言"可当场自证。
冻结态取标记固定找 **exe 同级**（不是 cwd、不是解包临时目录）。

**第二起打包态编码事故**（同族 B10-3 的下一层）：`daedalus-cli.exe --json doctor > x.json` 之后
`json.load` 抛 `UnicodeDecodeError`——`--json` 走 stdout，编码跟随**控制台码页**（GBK），
机器读的契约被码页绑住了。**修法**：`--json` 时 stdout **固定 UTF-8**，人类可读输出继续跟随码页
（`_make_output_safe(json_mode)`）。**只有打包态管道冒烟能发现**——源码态在 Git Bash 里永远是 UTF-8。

**影响面**
* 门禁：S10 新增 E 组 8 项（27→28）、S9 新增 F4（14→15）；全套 **12 门 249 项全绿**。
* `packaging/installer.nsi` 写 `lang=`；`ui/*` 里除 `i18n.py` 外**零硬编码可视中文**（门禁扫 AST 字面量）。
* 台账新增 `B18-1…B18-8`（含一条我自己的错：用脚本做字符串替换改 `.py`，**替换没匹配上却报成功**，
  导致修了等于没修——纪律改为"改 `.py` 一律用编辑器工具，不用字符串替换"）。

## 2026-09-23 · 重新打包：封住「改装分支冒充 playwright 驱动」的静默混装；1 小时长跑跑满通过

**为什么重新打包**：安全自审修了 5 处（凭据脱敏/槽位强制等）之后，老包体已经落后于源码；
机主要求重打并把老包体清掉。**结果又一次证明"重新打包"是必要的**——因为打包面上还藏着一个
只在制品里出现的问题。

**发现（本轮最值钱的一条）**：`patchright`（playwright 的**反检测改装分支**）在安装时带了一个
**名叫 `hook-playwright.sync_api.py` 的 PyInstaller 钩子**，内容却是 `collect_data_files("patchright")`。
PyInstaller 按模块名找钩子 → 给 `playwright.sync_api` 收数据时用了它 → 包里是**改装分支的 node 驱动**：
Python 侧正版 **1.62.0**、驱动侧 patchright **1.61.1**。
后果：本工程「**未改装的浏览器**」这条边界承诺在打包后**静默失效**；运行期的路径自证看不出来
（模块名仍然叫 `playwright`）；而且**首轮打包就已经这样了**，我当时没查包内布局。
`Analysis(excludes=[...])` 挡不住它——排除的是模块图，挡不住别人钩子收的数据文件。

**三层封堵（都验证过）**
1. `packaging/hooks/` 放我们自己的同名钩子（PyInstaller 的 `hookspath` **优先于**分发版自带钩子）→ 抢回控制权；
2. `tools/build.py` 产物核对加**硬断言**：包里必须有 `_internal/playwright/driver/package/browsers.json`，
   **绝不许**出现 `_internal/patchright|rebrowser|undetected_playwright|playwright_stealth`；
   实测：修复前那次构建**被判失败**（拦住了），修复后四条断言全过；
3. `env/browser.py` 的自证加第三重：**driver 版本必须与 Python 包版本一致**（专抓这种混装）——
   前两重（路径名/发行包名）在混装场景下都看不出来。
   顺带修：`browsers.json` 缺失时退回"扫已装浏览器"，不再谎报缺件（打包态实测踩到）。

**打包后实测**：`dist/daedalus-cli.exe version` ✓；`doctor` ✓ —— **「浏览器：可用（chrome.exe）」**，
且 GBK 控制台重定向下不再崩溃（上一轮修的那条在制品里也验证了）。

**1 小时长跑（清单 L5）跑满并通过**
* **24,400 任务 / 122 轮 / 60 分钟**（期间与 4 次 PyInstaller 构建抢 CPU，吞吐偏低属预期）；
* **跑丢 0 行**（台账 `new` = 实际任务数）；内存 34.2 → **19.9 MB**（斜率 **−0.60 MB/分**，不涨）；
  句柄斜率 −0.01/分；指标样本恰好停在容量 2048（有界）；关闭后自有线程归零、队列排空、`all_ok=true`。

**交付物**：`docs/18-Bug与错误日志台账.md`（机主要求的"bug/错误日志"，26+ 条真实问题，
每条含**报错原文 → 根因 → 修法 → 谁抓到的 → 防复发机制**，并总结了 5 条反复出现的教训）。

## 2026-09-23 · 安全审计（自审）：5 处真问题已修 + 1 处记录不修（12 门 240 项全绿）

**为什么是自审**：用户 @ 了 claude-security 插件，但它的扫描流水线依赖 **Claude Code 工作流门面**
（`parallel()` / `pipeline()`），在 ZCode 的动态工作流里不可用；插件自己的规矩**明确禁止**
"用自己的 agents 顶替它的 researchers/verifiers"（那样出来的报告会声称一次从未发生过的验证）。
所以按用户选择改**我自己的对抗性自查**，并在 `docs/17` 文首**明确标注它不是那份带三方验证封印的报告**。

**交付物**：`tools/security_probe.py`（28 项对抗性电池，离线）+ `docs/17-安全审计（自审）.md`。

**发现的真问题（5 修 1 记）**
* 🔴 **凭据泄漏是可达配置**：把 `log_url`/`log_text` 都关掉 → `token=`/`Authorization:`/`Cookie:`
  明文进日志——等于把 T1 的「日志无敏感」红线做成了选项。修：凭据走独立通路
  `sanitize_credentials()`，**不吃任何开关**；两个开关只管非凭据隐私。门禁新增 **C2b**（开关全关仍须脱敏），
  C2 改用非凭据参数验正交性。
* 🔴 **`sanitize_url` 三类缺口**：`https://user:pass@host`（Basic Auth 口令）**完全不脱敏**；
  `;token=`（分号分隔）与 `#token=`（fragment）漏；OAuth `code=` 漏。全部补齐，并验证
  **不误伤**（`id/q/uid/pkg` 原样）与**不吃掉后续正文**。
* 🟠 **文本里的 header 转储不脱敏**（`Authorization: Bearer X`、`Cookie: sid=X`）→ 新函数处理。
  **顺序有意**：先 scheme 再 header——反过来会把 `Bearer` 当值吃掉、剩下裸 token 认不出来（实测踩过）。
* 🟠 **结构化字段键名是 `cookie`/`token`/`sid` 时整个值不脱敏** → 键名命中凭据表即**整棵子树抹掉**。
* 🟠 **浏览器槽位只记账、没有强制**：并发 `observe()` 能无限开上下文（声明了槽位却没人管）→
  `BoundedSemaphore` + **非阻塞**获取，拿不到就明确拒绝、**不排队**（排队会把容量不足藏起来）。
  门禁新增 S8-D4（满槽零启动 / 页槽失败归还上下文槽 / 归还后仍可用）。
* ⚪ **记录不修**：卸载器写 `%TEMP%\…bat` 后执行（NSIS 延迟扫尾）。判定理由写在 `docs/17` §四：
  temp 是每用户私有、脚本先截断再写、替代方案（`Delete /REBOOTOK`）会留残骸——**是有意取舍**。

**顺带修掉的工程问题**：界面性能探针在**机器忙时测不准**（后台长跑抢 CPU 时同一套代码的停顿
从 0.0ms 变成超线，白查一轮）。修：探针输出 `machine_load_pct` 与 `measurement_trustworthy`，
门禁据此 **SKIP**（写明"请在空闲机器复测"）而不是 FAIL——"机器忙"不该伪装成"性能回归"。

**验证情况（自审的诚实边界）**：入网闸 34 种绕过形态零漏报、公网字面量零误拦；302 → 云元数据
被逐跳复检拦下；脱敏零明文残留；FTS 27 种畸形查询不炸且合法查询仍命中；路径穿越三面不逃逸；
`src/` 零 `shell=True`/`eval`/`exec`；八项资源上限逐条成立；容器解析有大小闸。
**没查**：依赖供应链 CVE、二进制产物完整性、干净机器安装、原生解析器 fuzzing、24h 长跑
（都写在 `docs/17` §五，并给了复现/补充方法）。

**门禁**：12 门 **240 项**全绿；安全探针 28/28；8 个提交（每个修复单独提交，纪律从本日起执行）。

## 2026-09-23 · S9 完成：命令行（门禁 13/13；十门 193 项全绿）

**做了什么**（2 个新模块 + 13 项门禁）

**本轮抓到 3 个真 bug（第一个是拦路级的）**
* 🔴 **robots 自递归 → 全站被拒**：`RobotsCache._fetch` 调 `Fetcher.open`，而后者**先查 robots 规则**
  ——于是"取 robots.txt"这个请求自己又要过 robots，成了**纯递归的规则查询**（实测 **一个网络包都没发**），
  最终把**每个首次访问的域**判成"完全禁止"。等于整台引擎采不到任何新域，而 S1–S8 的门禁全都没碰到
  真拼接（它们都注入了 robots 桩）——**这就是"桩太多会漏真 bug"的实例**。
  修法：`open_for_robots()` + 线程级重入守卫（跳过的只是规则层，**闸与限速照旧**）；
  回归钉加在 S4 门禁（G1：首次访问 = robots.txt + 目标页各一次、Disallow 仍拒、缓存与重入守卫生效）。
* 🔴 **`collect` 跑完空转五分钟**：worker 的收工条件写成"领不到活就等到 `idle_timeout`（默认 300s）"，
  用户看到的是"命令卡住不返回"。改成"**队列空 且 没有在飞任务**"才收工（不能只看队列空——
  别的 worker 手上的任务可能还要派生子任务）。实测：0.8s 返回（原来 300s）。
* 🟡 **写线程没有顶层崩溃保护**：一旦意外崩，线程静默退出，之后**每个写入干等 30 秒超时**
  （表现为"整台机器没反应"，完全查不出原因）。修法：崩了转死信 + 记 `_crash` + 重连继续；
  `run_now` 超时改成带原因的 `RuntimeError`（存活/队列深度/最近崩溃），未启动则明确拒绝写入。

**验了什么**（`s9_gate.py` 13/13）
* `collect` 真跑闭环：2 任务 → 原始层 2 + 派生 2 + 台账 `new: 2`（CLI 关引擎后**用独立只读连接**核库）；

## 2026-09-23 · S6 完成：路由收口 + 端到端接线（门禁 11/11 全绿）

**做了什么**（1 个新模块 + 2 处收口 + 11 项端到端门禁）
1. **任务运行器** `core/runner.py`：把分层串成闭环——
   `Task → Router.start → 环境取流 → **原始层先落盘** → 解析/质量闸 → 证据 → Router.on_evidence
   → Frontier.commit_done（CAS + 产物 + 派生行同一事务）/ mark_failed（限流与重试分账）→ 变更台账`。
   运行器**不选环境**（那是 Router 的职责），只把每一步落到实处；自身异常一律兜住并记死信。
2. **路由收口** `core/router.py`：`parser_failed` 改成**与阶段无关**的规则——"解析失败但原始已存 →
   延期解释（不是失败）"。以前这条只在制品阶段有，直连阶段会掉进"不猜"兜底被误判成 `dead`。
3. **Frontier 接口去刺** `frontier/frontier.py`：证据入参统一为"单条 / 一串 / 空都接"
   （`_evidence_list`）；`mark_failed` 新增 `state=` 透传**路由已裁决的终态**，不再自己二次推导。

**为什么（本轮抓到 5 个真 bug，全是门禁逼出来的）**
* **接口形状不一致 → 一次炸五个用例**：`commit_done` 收一串证据、`mark_failed` 收单条，
  运行器传证据链时变成 `[[…]]`，`_write_evidence` 里 `ev.at` 直接 AttributeError。
  教训：**同族接口的参数形状必须一致**，否则是等着出事的刺。
* **`large_object` 信号被"过滤器"吃掉**：运行器里有个 `from_response_safe()` 会跳过 `large_object`，
  结果 `application/octet-stream` 永远升不到制品环境（跨环境任务形同虚设）。
  改成"事实是什么信号就什么信号，改道交给 Router"。
* **`policy_denied` 被吞成 `dead`**：`mark_failed(retryable=False)` 一律置 `dead`，
  于是 robots 拒绝在库里看不出是"被规矩挡住"。终态是路由判的，Frontier 只该记账。
* **限流重试不记账**：路由给出"重试"后运行器没有递增 `attempts/throttles`，
  预算判定永远读 0 → 坏目标只能靠转移次数兜住。现在**两本账分开**递增 + 退避阶梯（sleep 可注入）。
* **`lease_lost` 的语义重新想清楚了**：原始层在**执行期**就落盘（Capture First：进程随时会死），
  CAS 保护的是"任务完成"这个状态与派生行。这不是妥协——原始层是**内容寻址 + 幂等写**
  （同字节 → 同 sha256 → `INSERT OR IGNORE`；不同字节 → 两行，各自是当时的真事实），
  截断响应会标 `too_big`、不伪装成完整产物。这条**取舍**写进了 `runner.py` 文件头，
  门禁也照此断言（派生行必须 0，原始层允许 ≤1 且不许重复）。
* 另有 3 处**桩不忠实 / 用例设计错**：假的 fetcher 不执行 robots（那"零出网"断言测的就不是产品），
  拿 UTF-16 二进制当"解析失败"（其实解码成功、走的是正常路径），单次 429 当"连续限流"（应给两次 + 预算）。
* **证据只写人话、不写事实**：质量拒收的证据 `facts` 是空的，事后既解释不清也离线判不回来。
  现在响应事实（状态码/类型/体积）跟随裁决一起入链，拒收/解析失败都带结构化字段。

**影响面**
* 闭环成立：一条任务能真的走完"取流 → 原始层 → 派生行 → 打卡 → 台账 → 发现子任务"；
  跨环境（直连 → 制品）、被拦（robots → `policy_denied`、零出网）、限流（独立计数 → 死信）、
  失守（CAS → 派生行一行不写）四条路都各有门禁用例。
* 每一步都可解释：证据链保存"看到了什么 → 决定了什么 → 为什么"，字段齐全可回放。

裸出网调用 0 处（`urllib.request`/`socket` 只出现在 `net/ssrf_gate.py`），重放面不引用网络。

   **不改进程 locale**（给子进程传 `LC_ALL=C.UTF-8` + 显式 UTF-8 解码）、缺件抛 `ToolMissing`（硬报错）、
   超时返回 `timed_out`、`readiness()` 就绪探测报告、`safe_output_name()` 纯 ASCII 输出名。
3. **媒体环境** `env/media.py`：`probe` / `download_large`（断点续传 + 契约）/ `download_hls`
   （分片并发 + 按序 + 契约）/ `fetch_document` / `capability()`（**缺件要说清哪些能力被禁用**）。
   出网仍然只经 `Fetcher`（分片、密钥、直链都是远端给的不可信输入）。
4. **HLS 分片并发**（P13）：`download_hls(concurrency=4)` 并发下载 + 各自 IV 解密，
   **拼接顺序由分片序号决定**（并发不改顺序）；ffmpeg 调用支持 `runner` 注入统一子进程面。
5. **制品/文档元数据解析** `understand/parsers/mediainfo.py`：图片（PIL）/ 容器（zipfile）/
   媒体（ffprobe）/ PDF（结构粗计）；`run_isolated()` **进程隔离**（spawn + 超时**终止**），
   进程槽位容量来自注册表——**缺省即拒绝**。

**为什么（本轮抓到的问题）**
* **进程隔离的入口必须是模块级函数**：`run_isolated` 一开始把子进程入口写成**闭包**，
  spawn 启动方式无法 pickle → `PicklingError`。门禁 D2/D3 直接暴露。改成模块级 `_child_entry`。
  （顺带体会到隔离的好处：**超时可以真的终止进程**——线程做不到这件事，门禁 D3 实测 0.8s 内终止。）
* **字符串里嵌半角引号**又犯了一次（`"可播"` 写在双引号字符串里 → SyntaxError）。
  第 4 次了，已列进 `docs/14-……`？——不，记在这里：**中文引号一律用「」/【】，别再混半角**。
* 两处**测试素材不真实**：纯色 PNG 被压到 161/468 字节，契约正确判"过小"。
  给测试图加噪声（真图片大小）后通过——**产品行为是对的，错的是我的假数据**。

**影响面**
* "下载成功 ≠ 产物合格"这条现在有强制执行点：媒体/文档产物一律过契约，不合格带原因判失败。
* 缺件（没 ffmpeg/ffprobe）从"静默降级"变成"明确告知 + 禁用对应能力"，GUI/CLI 都能读 `capability()`。

## 2026-09-23 · S4 完成：环境①直连网络 + 发现链 + 执行面（门禁 24/24 全绿，跑 5 次稳定）

**做了什么**（6 个模块 + 24 项门禁）
1. **URL 规范化** `frontier/urlcanon.py`：13 条"做"的规则 + **3 条"刻意不做"的显式声明**
   （尾斜杠不归一、签名参数不丢、不跟随重定向/不做语义改写），另有指纹函数供去重与队列主键。
2. **HTTP 缓存** `net/cache.py`：按 URL 存响应 + **条件请求**（`If-None-Match`/`If-Modified-Since`），
   `304` → **复用旧内容并刷新时间**；**数量上限 + 最久未用淘汰**（只写不删是磁盘慢性泄漏）；
   元数据里的 URL **原样**（运行态钥匙不脱敏）。
3. **直连网络环境** `env/net.py`：超时 (5,15)、重试（退避 = `min(8, 0.5·2^n) × 抖动`）、
   **限流不在这一层重试**（`Throttled` 直接上抛，退避由任务层统一管）、**响应体 5MB 打标 too_big 并跳过解析**、
   **编码探测顺序**（响应头 → BOM → meta → 兜底）、Cookie 接线（取不到给**可读原因**）、
   **代理只走环境变量**、每次取流产出证据。
4. **发现链** `capture/discovery.py`：HTML 链接 / 订阅条目 / 站点地图 / **内嵌 JSON** 四路融合 →
   规范化 → **策略过滤**（站内站外 + 闸 + robots），被拒的**带原因**返回（不许静默丢）。
5. **执行面** `exec/pools.py`：`BoundedQueue`（**maxsize 必填**，满则阻塞=背压）、
   `ManagedPool`（容量来自注册表、**缺省即拒绝**、有界提交、**任务级看门狗**、
   超时**标记作废而不杀线程**、优雅关闭并让线程数回落）、`Pipeline`（三段流水线，段间有界）。
6. **域冷却持久化** `net/cooldown.py`：冷却状态落 `cooldowns` 表并在启动时恢复——
   Kiana 的重启即忘会让"被拦即降速"当场失效。

**为什么（本轮抓到两个真 bug，都是"偶发丢数据"型）**
* **流水线关闭顺序错**：`stop(drain=True)` 只 join 了第一段队列，下游队列还没排空就把 worker 停了
  → 表现为"200 条里偶发少几条"（跑两次分别 199/200、193/200）。修法：**逐段按序 join**（0→1→2）。
  这类 bug 最阴：不是每次必现，靠"跑一次过了"永远发现不了——门禁跑 5 次就是为了这个。
* **有界队列把 `queue.Full` 抛了出来**：调用方拿到异常而不是 `False`，背压语义在调用点会变形。
  改成"满则阻塞、超时返回 False、不抛异常"。
* 另外把两条**刻意不做**的归一规则写进 `RULES` 并在门禁里断言（尾斜杠 `/a` ≠ `/a/`；
  `token/sig` 不当跟踪参数丢掉）——否则后人"顺手优化"一下就会引入 403 或重复抓取。
* 顺手处理一条安全扫描意见：退避抖动用了**普通随机**（提示"随机数不安全"）——这是刻意的
  （要的是错开重试时刻，不是密码学随机），已在代码注释里写明理由，按"评估后保留"处理。

**影响面**
* 直连网络的"取一个 URL"整套规矩齐了：**限流 ≠ 重试**、**超限不解析**、**304 复用**、
  **编码说得清依据**、**被拒必有原因**、**代理只认环境变量**。
* 执行面第一次落地：线程池是**资源**（要声明、要容量、要背压、要看门狗、要优雅关闭），
  这为 S8 的浏览器槽位与 S5 的子进程槽位铺好了同一套模型。

**下一步**：S5（环境③制品与媒体：Range/断点续传接线、产物验证、HLS+AES-128、ffmpeg 子进程、文档解析）。

## 2026-09-23 · S3 完成：捕获面 + 理解面骨架（门禁 17/17 全绿）

**做了什么**（9 个模块 + 17 项门禁）
1. **原始层** `capture/rawstore.py`：**内容寻址**（sha256 前两位分片）、**逐记录压缩**
   （文本类 >1KB 压 gzip，后缀 `.bin.gz` 自描述）、**血缘齐全**（URL/状态/头/MIME/大小/hash/
   来源/会话/父任务/发现路径）、**原子落盘**（tmp + `os.replace`）、`verify()` 能证伪篡改。
2. **索引** `capture/index.py`：数据文件与索引分离（WARC/CDX 的经验）；按内容/URL/父任务/时间/
   URL 片段查询。
3. **离线重放** `capture/replay.py`：`Reparser` 扫原始层 → 探测 → 解析 → 归一 → 质量闸 → 投递；

4. **探测链** `understand/detect.py`：魔数 → 扩展名 → XML 根 → 声明的 Content-Type → JSON → 文本 → 兜底，
   每个结论都带 `how`（凭什么这么判）与 `confidence`；认不出**如实说认不出**。

7. **质量闸** `understand/quality.py`：正文长度 + 字段齐全度 + 空壳惩罚；`0.12` 阈值；
   **拒收 ≠ 重试**（记为 failed 并视为"已处理"，附可读原因）。
8. **变更台账** `understand/ledger.py`：五态（新增/未变/更新/失败/被策略拒绝）+ 可读摘要 + JSONL 追加。

**为什么（本轮修正的三处语义问题）**
* **一份原始数据可能产出多条记录**：订阅（RSS/Atom）与站点地图天然是"一批条目"。
  第一版把它们硬塞成"一个页面"，于是没有 `text` 字段 → 被质量闸全拒（门禁 D1/D2 直接暴露）。

* **JSON 文档需要"正文形态"**：只给"路径:值"列表的话，质量闸与去重都没有可读内容可比 →
  解析器补一个紧凑渲染的 `text`。
* **通用容器后缀不该阻断探测链**：`feed.xml` 第一版被判成泛泛的 `xml`（扩展名先命中），
  丢掉了 rss/atom/sitemap 的区分。改成 `.xml/.txt/.bin/.dat/.rss/.atom` 只当**弱提示**，
  继续走根元素/内容判断；全链无结论时才用它兜底。
* 顺手修一处我自己的编辑事故：改 `_EXT_MAP` 时误删 `.jpg/.jpeg` 两行（复查时发现并补回）。

**影响面**
* "先捕获后理解"闭环跑通了：**写原始 → 离线重放 → 派生记录**，重放不联网、可增量、可解释
  （第一条"未变"也是一等结果）。增删解析器只影响理解面，事实层不动。
* 验收里最容易翻车的一条现在有门禁：`reparse` **不联网**（模块级扫描 + `daedalus.net` 出现即 FAIL）。

## 2026-09-23 · S2 完成：核心骨架（门禁 20/20 全绿）

**做了什么**（9 个模块 + 20 项门禁）
1. **统一任务模型** `core/task.py`：Task（身份/目标/策略/预算/运行态）、`TaskKind`、`TaskState`（**有界**）、
   `ResourceRequest`（**显式声明**）、幂等键（`kind|target` 的哈希）。派生任务默认**不声明网络资源**——
   于是它物理上没法出网。
2. **证据** `core/evidence.py`：`Evidence(signal, decision, reason, stage, facts)`，
   信号集合**有界**，`from_response/from_parse/from_decision` 把"原始事实"抽成信号（不猜内容）。
3. **预算** `core/budget.py`：时间/字节/转移次数/重试/限流五个维度，含 `small()/media()` 两个档位。
4. **资源注册表** `core/registry.py`：**缺省即拒绝**（浏览器与进程池默认容量 0 → 要就被拒）。
5. **证据驱动路由** `core/router.py`：L0–L5 阶梯、**转移有界**、每次转移都给 reason、
   **未启用环境只记候选**（V0.1 不含浏览器：遇到空壳只记 `browser_candidate` 并终止，不偷偷起环境）。
6. **迁移** `frontier/migrations.py` + **连接工厂** `store/db.py`：`user_version` 驱动、幂等、
   版本号由迁移脚本**自己**写；每个连接都设 WAL/busy_timeout（含读连接）。
7. **单写线程** `store/writer.py`：有界提交队列（满则阻塞=背压）、批提交、**每个任务一个 SAVEPOINT**
   （一条坏数据只回滚自己，不拖垮整批）、失败必写死信（带 SQL 轨迹）。
8. **死信** `store/deadletter.py`：JSONL 追加 + 可选入库 + **导出成 `.sql` 供人工核对后执行**
   （刻意**不**自动重放：历史语句带当时的参数值，重放不幂等，而且不该有动态执行面）。
9. **前沿** `frontier/frontier.py`：有界入队 + 幂等入队、租约（返回**本次真实** `leased_at`）、
   心跳**续 `lease_expires`**、CAS 打卡与产物写入**同一事务**（失守则一行不写）、
   失败记账（**限流只加 throttles**）、过期租约回收（能重试回 `retry`，超限转 `dead`）、看门狗扫描。

**为什么（本轮抓到两个真问题）**
* **死信写库撞锁，把写线程卡停 30 秒**：`DeadLetter.write()` 一开始用**独立连接**写 `deadletter` 表，
  而写线程的批事务还开着 → `database is locked`（busy_timeout 30s 阻塞）→ 后续任务全部超时。
  门禁 C2 直接把这个现象暴露成"坏任务拖垮整批：ok=58 失败=3×TimeoutError"。
  修法：**死信的表写入必须走写线程那同一个连接**（`write(..., conn=conn)`）；文件写入不受影响。
* **本机安全策略的规则比预想更严**：`execute()/executescript()` 的第一个参数必须是**字符串字面量**——
  连"模块级 SQL 常量"传进去也会被判为动态 SQL。为此我把写探查方法改成了"**先写探针文件**看清规则"
  （7 种写法一次测出哪些被拦），再按规则重写：`frontier.py` 的 SQL 全部内联、
  迁移 DDL 改成 `migrations.py` 里的内联字面量（`.sql` 迁移文件因此删除，`schema.sql` 降级为参考对照）。
  这条写进 PENDING/纪律，避免后人"顺手重构回常量"。
* 顺带修正两处我自己的测试错误：`raw_artifacts` 本来就没有 `simhash` 列（该查 `pages`）；
  savepoint 修好后"坏任务自己的写入也被回滚"，所以落库行数是 60 而不是 61（断言改成"坏行必须不在库里"）。

**影响面**
* 出网、写库、任务状态三条路径现在都有单一咽喉：`Fetcher` / `SingleWriter` / `Frontier`。
* "限流≠重试""CAS 在写产物前""心跳续到期时间""坏数据不拖垮整批""重启能续"这五条不变量都有门禁盯着。

**下一步**：S3（捕获面 + 理解面骨架：内容寻址原始层、`reparse` 重放、探测链、解析器注册表、
规范化、去重/增量台账、质量闸）。
