# 10 · 完工检测清单（终检）

> **这是什么**：施工完成（S10 结束）之后、交付/发版之前执行的**逐条检测清单**。
> **不是什么**：不是施工计划、不是施工步骤——施工计划在批准的那份文档与 `docs/00`–`09` 里。
> **来源**：施工计划全部条款 +《02-踩坑总账》（44 条坑）+ Kiana 的 ARCHITECTURE / DEVLOG / BUILD /
> CLAUDE.md / 工程全景 / 优化计划 / bug_audit / 安装器检修状态 / GUI施工手册 / PENDING + UI 设计系统报告 v2。
> **权威源**：本清单与施工计划冲突时以施工计划为准；本清单只改本文件。

---

## 0. 怎么用这份清单

1. **执行时机**：全部阶段门禁通过之后、发版/交付之前。**执行前不要再改代码**——改一行就要重跑受影响的条目。
2. **记录三态**：`PASS` / `FAIL` / `未验证`（附原因与验证方法），每条尽量附**证据路径**（日志片段、报告文件、截图、命令输出）。
3. **FAIL 规则**：修完**重跑该条**，并重跑受影响的相邻条目（例：改了写库路径 → 重跑 G 组与 E 组）。
4. **"未验证"规则**：允许存在，但必须登记进 `PENDING.md`，并在交付说明里明确写出；**不许把"未验证"记成 PASS**。
5. **清单自身自检（先做）**：用"全部干净"与"全部崩坏"两个极端状态各扫一遍，确认清单能给出不同结论
   ——防的是"清零反而 FAIL / 假绿"这类门禁假红（Kiana 踩过）。
6. 只查"是否成立"，不查代码风格。
7. **一页汇总在 §P**；`FAIL > 0` **不得签字**。
