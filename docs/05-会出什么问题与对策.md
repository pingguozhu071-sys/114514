# 05 · 会出什么问题 → 对策（以及我们实际踩过的）

> 上半是"预先想到的坑 + 对策"，下半是**真实踩到的**（每次都有门禁或修复记录）。
> 这份文档的用法：改代码前先扫一眼自己那一条，别重复踩。

## 一、预先想到的坑（每条都有对策，且都落在代码里）

| 坑 | 症状（为什么难查） | 对策 | 落地 |
|---|---|---|---|
| **声明与行为不符** | 配置项解析了但没人判断、界面选项没连到引擎 | **只有一层映射**（`config.example.toml → DEFAULTS → 组件`）+ 往返接线测试 | `config.py`；S1 F 组 |
| **无界队列** | 平时没事，一上量就 OOM（"内存慢慢涨"） | 三条队列 + 写队列全部有上限，满则**阻塞**（背压） | `exec/pools.py`；S2/S7 |
| **限流当失败** | 任务永驻重试队列，"没有待处理"的退出条件永不成立 | 限流独立计数；连续 N 次转死信；`Retry-After` 带上限 | `task.throttles`；S2/S6 |
| **批量写溢出整批回滚** | 表现为"数据静默丢失"（SimHash 超 63 位） | 入库前 `clamp63` + 逐条 SAVEPOINT + 坏数据进死信 | `frontier/dedup.py`、`store/writer.py`；S2 |
| **跟 302 进内网落盘** | 外部 URL 302 指向内网 → 内网正文被当图片存下 | 关自动跟随 + **逐跳复检** + 每环境各自建闸 + 专属拦截码 | `net/ssrf_gate.py`、`env/browser.py`；S1/S8 |
| **DNS 永久缓存 → rebinding** | 首次解析合法，之后指向内网 | 90s TTL + 解析结果只用于判定，不用于连接 | `net/ssrf_gate.py`；S1 |
| **脱敏挂 root logger / 先存后脱敏** | 日志里出现明文 token；或脱敏后的东西才落盘（原始数据被毁） | 包装 `Handler.__init__` + 覆盖 `extra`/JSON + **先脱敏后落盘**；**原始层永不脱敏** | `obs/logging_sanitizer.py`、`obs/policy.py`；S1/S3 |
| **密钥弱兜底 / 谎报加密** | 源码里有兜底密码；或提示"已加密"而实际是明文 | 读不到就**报错**；提示语由实现结果决定 | `privacy/secrets.py`；S1 |
| **看门狗打回已完成** | 已完成的任务被改回待重试 → 重复采集 | 状态守卫（CAS 的 `WHERE state IN ('leased','running')`） | `frontier/frontier.py`；S2 |
| **锁冲突当被抢走** | 读连接没设 `busy_timeout` → 把"锁等待"误判成"任务被抢" | 每个连接（**含读连接**）都设 PRAGMA | `store/db.py`；S2 |
| **单页挂死冻整批** | 一个超时页面卡住整个批次 | 任务级看门狗 + 标记作废 + 线程自退（**不 kill 线程**） | `exec/pools.py`；S4 |
| **产物坏却返回 0** | 命令退出码 0，产物是错误页 | 产物契约（大小/格式/MIME/哈希）+ 重做闸 | `capture/artifacts.py`；S5 |
| **远端子 URL 直连** | HLS 清单里的分片/密钥 URL 是"远端给的数据" | 分片、密钥、直链**都过同一个咽喉** | `adapters/hls.py`；S1 G2、S5 |
| **缺件静默不打进包** | 装完才发现没 ffmpeg/浏览器 | **缺件硬报错**（构建期中止 + 运行期就绪探测） | `env/media.py`、`tools/build.py`；S5/S10b |
| **装卸载动到正式环境** | 卸载时删了别人的文件/用户数据 | `un.` 前缀 + 条件化清理 + 数据默认保留 + 测试环境验证 | `packaging/installer.nsi`；S10b |
| **GUI 事件洪泛 / 回调重建控件** | 实测停顿 7.6 秒 | 防抖 250ms + 忙时挂起 + 代数号守卫 + `postEvent`；控件树只建一次 | `ui/render.py`；S10（C 组） |
| **门禁假绿** | 输出里有 PASS 但其实是没跑/断言被注释 | **以退出码为准** + 项数校验 + 桩签名与真接口一致 | `tools/gates.py`、各 gate；纪律 |
| **文档漂移 / 未完成假装完成** | 文档说做了、代码没做 | 标权威源 + `PENDING.md` 登记 + `docs/03` 明确列"未验证" | 纪律 |

## 二、真实踩到的（按发现顺序；每条都在 DEVLOG 有完整记录）

| # | 现象 | 根因 | 谁抓到的 | 修复 |
|---|---|---|---|---|
| 1 | 探针文件以非零码退出，但门禁报绿 | 门禁只看输出没看退出码 | 自查 | 门禁统一以退出码 + 项数双判 |
| 2 | 部署后目标站收到"我们"的请求带明文 token | `sanitize_url` 的正则 `[^&#]+` 吃掉了 URL 之后的整段文字 | **自建门禁** | 正则收紧为 `[^\s&#\"'<>]+` |
| 3 | robots 规则跨 UA 组泄漏 | 分组解析缺 `last_was_ua` 复位 | S1 门禁 | 加复位 + 用例 |
| 4 | 死信写入把写线程卡死 30 秒 | 死信另开连接 → `database is locked` | S2 门禁 | 死信写用**写线程自己的连接** |
| 5 | 流水线 `stop` 只 join 第一条队列 → 丢数据（199/200） | 关闭顺序错 | S4 门禁（跑 5 次才复现） | 按阶段顺序 0→1→2 join |
| 6 | `BoundedQueue.put` 抛 `queue.Full` | 与"满则阻塞"的契约不一致 | S4 门禁 | 返回 False（阻塞语义） |
| 7 | 进程隔离入口写成闭包 → `PicklingError` | spawn 无法 pickle 闭包 | S5 门禁 | 改成模块级 `_child_entry` |
| 8 | 流水线数据静默少一条 | 队列/背压边界 | S4 门禁 | 同上（第 5 条） |
| 9 | 契约把测试图判"过小" | 测试素材是纯色 PNG（压缩到 161 字节） | S5 门禁 | **产品对、素材错**：给测试图加噪声 |
| 10 | `large_object` 永远升不到制品环境 | 运行器里有个 `from_response_safe()` 过滤掉了该信号 | S6 门禁 | 删掉过滤器：事实是什么信号就是什么 |
| 11 | `policy_denied` 被吞成 `dead` | `mark_failed(retryable=False)` 一律置 dead | S6 门禁 | 终态由路由裁决，frontier 只记账 |
| 12 | 限流重试不记账 | 运行器没递增 `attempts/throttles` | S6 门禁 | 两本账分开递增 + 退避 |
| 13 | 一次改接口形状，五个用例同时红 | `commit_done` 收一串证据、`mark_failed` 收单条 | S6 门禁 | 统一 `_evidence_list` |
| 14 | `collect` 跑完卡住五分钟 | worker 收工条件写成"等到 idle_timeout" | S9 门禁（超时） | 改成"队列空 **且** 无在飞任务" |
| 15 | **取 robots.txt 自己又要过 robots → 纯递归 → 全站被拒** | `RobotsCache._fetch` 调 `Fetcher.open` | **S9 端到端**（CLI 真跑） | `open_for_robots()` + 线程级重入守卫；S4 门禁钉住 |
| 16 | 写线程崩了整个引擎静默停摆（写入干等 30s） | 写循环没有顶层崩溃保护 | S9 门禁（超时） | 崩→死信+`_crash`+重连；`run_now` 超时给原因 |
| 17 | **读响应体会让 Chromium 把资源再取一遍，且第二遍丢掉我们的 UA** | route 拦截下读 `body()` 触发重取 | S8 门禁（3/3 复现） | 只对 document/xhr/fetch 读体；UA 两处给（context + 启动参数） |
| 18 | 同进程反复启停 playwright 撞 asyncio 循环 | sync API 的驱动进程反复 start/stop | S8 门禁 | 进程级单例 + `shutdown_playwright()` |
| 19 | `max_observed` 参数形同虚设 | `_trim` 读的是模块常量不是实例参数 | S8 门禁 | 传实例值 |
| 20 | `capture_bodies=False` 时渲染后的 DOM 仍被写入 | 那个开关没管到底 | S8 门禁 | 加上判断 |

## 三、还没踩但随时可能踩的（写下来当预案）

| 风险 | 预案 |
|---|---|
| 目标站结构大改 → 解析全失败 | 因为**先捕获后理解**，原始数据都在：改解析器 → `daedalus reparse` 重扫，不重新联网 |
| 磁盘写满 | `disk.free_pct` 告警（默认 <10% 报 warn）+ 死信里有明确记录；原始层写入失败不阻断任务状态机 |
| 站点返回巨大响应 | 直连 5MB 上限打标 `too_big`（只捕获不解析）；制品通道走契约与 `max_bytes` |
| 一个域把连接占满 | 每域并发上限（默认 5，上限 8）+ 礼貌间隔原子预约 |
| 用户手改 settings.json 改坏 | 回退默认值并在设置页显示原因（不静默） |
| 便携版被拷到只读介质 | 数据根解析失败 → 明确报错而不是假装成功 |
| 浏览器版本升级导致元素定位失效 | 观察面只记事实（URL/状态/大小），不依赖 DOM 结构做关键判断 |
